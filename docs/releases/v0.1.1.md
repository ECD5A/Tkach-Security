# Tkach Security v0.1.1 — release candidate

This document describes the `v0.1.1` candidate. It is a preparation record,
not proof that the tag or any external package publication has completed.

## Candidate changes

- Harden the real loopback-effect regression harness against transient
  nonblocking `accept` errors and the macOS half-close race.
- Keep the cross-platform authorization test repeated and fail with receiver
  diagnostics when a platform-specific regression occurs.
- Require npm and PyPI publication to originate from a published GitHub
  Release, checked out at that exact release tag.
- Add protected OIDC publication workflows for the seven Rust crates, with
  dependency-ordered publication and registry visibility polling.
- Preserve the Windows executable filenames in release ZIP archives.
- Align all Rust crates, Python/JavaScript adapters, Cargo.lock, and MCP
  metadata on the single `0.1.1` version contract.

## Release gates

The candidate is not complete until all of the following have independently
passed:

1. GitHub CI is green on Linux, macOS, and Windows for the candidate commit.
2. The strict `v0.1.1` tag preflight builds, installs, and smoke-tests both
   CLI binaries and all signed release archives.
3. The crates.io Trusted Publisher configuration is present for every crate,
   and the protected dependency-ordered publication completes.
4. The GitHub Release is published only after its draft artifacts pass review.
5. npm, PyPI, OCI, and MCP workflows complete from that published release;
   registry records are checked directly afterwards.
6. Clean-machine onboarding and the final local security/reliability review
   pass without changing the frozen Core contract.

The repository must not describe a candidate package as published until the
corresponding registry API and release artifact have been verified.

## Owner actions required outside the repository

Before publication, configure these one-time Trusted Publisher records:

- PyPI project `tkach-security-client`: owner `ECD5A`, repository
  `Tkach-Security`, workflow `publish-pypi.yml`, environment `pypi-publish`.
- Each Rust crate on crates.io: owner `ECD5A`, repository `Tkach-Security`,
  workflow `publish-crates.yml`, environment `crates-publish`.

No long-lived npm, PyPI, or crates.io token belongs in this repository.
