# Tkach Security v0.1.1

Tkach Security v0.1.1 is the first release in which every supported public
distribution channel is driven by the same versioned, fail-closed release
contract. The Core security API remains frozen; this patch hardens tests,
packaging, and publication around it.

## Changes

- Harden the real loopback-effect regression harness against transient
  nonblocking `accept` errors and the macOS half-close race.
- Repeat the cross-platform authorization test and retain receiver diagnostics
  for platform-specific failures.
- Preserve `.exe` filenames in Windows release ZIP archives.
- Align all Rust crates, Python/JavaScript adapters, Cargo.lock, and MCP
  metadata on version `0.1.1`.
- Gate npm, PyPI, crates.io, GHCR, and MCP publication with protected GitHub
  environments and short-lived OIDC credentials.
- Publish Rust crates in dependency order and verify each registry record
  before continuing.

## Security boundary

The model remains untrusted data and cannot mint authority. Tkach still does
not claim a public internet gateway, TLS termination, Streamable HTTP, a cloud
control plane, host/OS compromise protection, or a generic executor. The OCI
runtime is non-root and loopback-only by default; MCP remains a local stdio
adapter over a separately started Tkach runtime.

No long-lived npm, PyPI, or crates.io credential is stored in the repository.
